# nvlocale

Локализация по ID для NVGT / AngelScript.

Не шаблоны вида `%1 has %2 %3`, а целые фразы: одна фраза — один ID, куски
подставляются как `{0}`, `{1}`. Переводчику видно всё предложение целиком,
поэтому порядок слов, падежи и согласование остаются в руках переводчика,
а не склеиваются из независимо переведённых обрывков.

## Что внутри

- `nvlocale.as` — сама библиотека, один файл, без зависимостей.
- `catalogs/en.lng`, `catalogs/ru.lng` — примеры каталогов (базовый и русский).
- `tools/plural_rules.py` — эталонная реализация правил склонения на Python.
- `tools/test_plural_rules.py` — 176 векторов CLDR, проверяют таблицу правил.
- `tools/lng_lint.py` — линтер каталогов: пропущенные ID, лишние подстановки,
  недостающие формы множественного числа.
- `tests/test.as` — тесты библиотеки на самом движке NVGT.
- `examples/example.as` — запускаемый пример.

## Быстрый старт

```angelscript
#include "nvlocale.as"
using loc;

void main() {
	init("catalogs", "ru");          // папка и язык; "" — язык системы
	screen_reader_speak(t("menu.start"));
	screen_reader_speak(t("ui.volume", "7"));
	screen_reader_speak(t("msg.picked_up", "Мила", t("item.whistle")));
	screen_reader_speak(tn("bag.items", 5));   // «В сумке 5 предметов.»
}
```

`init()` сначала загружает английский базовый каталог, потом запрошенный язык.
Если файла языка нет — остаётся английский, функция возвращает `false`.

Важно про пути: NVGT запускает скрипт, делая текущей папку самого скрипта.
Поэтому путь к каталогам считается от неё, а не от корня проекта.

## Формат `.lng`

UTF-8, построчно. Пустые строки и строки, начинающиеся с `#`, `;` или `//`,
пропускаются.

```
id[=]текст с {0} и {1}
bag.items.one[=]В сумке {0} предмет.
bag.items.few[=]В сумке {0} предмета.
bag.items.many[=]В сумке {0} предметов.
bag.items.other[=]В сумке {0} предмета.
```

- Разделитель — `[=]` (как в языковых пакетах Life in Nature) или обычный `=`.
  Если в строке есть оба, побеждает `[=]`, потому что он ищется первым.
- ID не может содержать пробелов и табов.
- Пробелы вокруг ID и текста обрезаются.
- Повторное определение ID перекрывает предыдущее — так второй файл может
  патчить базовый каталог.
- BOM в начале файла снимается.

### Экранирование и подстановки

Обработка идёт одним проходом, без двойного разэкранирования:

| В файле | В результате |
|---|---|
| `\n`, `\t`, `\r` | перевод строки, таб, возврат каретки |
| `\\` | один обратный слэш |
| `{{` и `}}` | литеральные `{` и `}` |
| `{0}`, `{1}`, … | аргумент с этим номером |
| `\q` (неизвестная escape) | обратный слэш сохраняется: `\q` |
| одинокая `{` или `}` | остаётся как текст |

`{{0}}` печатает буквально `{0}` и аргумент не подставляет.

## API

```angelscript
// Загрузка
bool init(const string &in dir = "lang", const string &in lang = "");
bool load(const string &in lang);                  // dir/<lang>.lng
bool load_file(const string &in lang, const string &in path);
bool load_base(const string &in lang = "en");      // только базовый
bool available(const string &in lang);
string detect(const string &in fallback = "en");   // язык ОС

// Язык
bool set_language(const string &in lang);
string language();

// Перевод
string t(id);                    // и перегрузки с 1..6 строковыми аргументами
string tn(id, double n);         // и перегрузки с 0..5 доп. аргументами
string t_args(id, const string[] &in args);
string tn_args(id, double n, const string[] &in args);

// Числа
string num(double v, int precision = -1);
string plural_category(double n, const string &in lang = "");

// Диагностика
bool has(const string &in id);
string[]@ missing_ids();
uint missing_count();
void clear_missing();
string[]@ parse_errors();
int parse_error_count();
void clear_parse_errors();
```

`tn()` подставляет число первым аргументом — это всегда `{0}`. Дополнительные
аргументы идут с `{1}`. Число форматируется с разделителем, принятым в активном
языке: `7.5` → `7,5` в русском, `7.5` в английском.

`num(v)` без точности печатает кратчайшую форму (`7` → `"7"`, `7.5` → `"7.5"`).
С точностью `num(7.256, 1)` округляет до `7.3` (и до `7,3` по-русски).

Если ID не найден, `t()` возвращает сам ID и запоминает его в `missing_ids()`.
Это удобно и в разработке, и в проде: на экране видно, какой именно ключ
потерялся, а в конце сессии можно выгрузить список.

## Склонение

Таблица правил — не DSL, а фиксированный набор из 23 функций CLDR. Их пишут
один раз в библиотеке, переводчику они не видны: он просто пишет варианты
`.one`, `.few`, `.many`, `.other` для своего языка.

Выбор варианта: `tn()` определяет категорию числа по CLDR для активного языка,
затем ищет `id.<категория>`. Дальше — цепочка откатов:

1. активный язык, `id.<категория>`
2. активный язык, `id.other`
3. активный язык, `id`
4. базовый язык, `id.<категория>`
5. базовый язык, `id.other`
6. базовый язык, `id`
7. вернуть сам ID и записать его в missing

Какие категории нужны языку:

- `other` — всегда обязателен, это последний рубеж.
- `one` / `other` — английский, немецкий, испанский, итальянский, турецкий
  и большинство «обычных» языков.
- `one` / `few` / `many` / `other` — русский, украинский, белорусский.
- `one` / `few` / `other` — сербский, хорватский, боснийский, болгарский,
  македонский (без `many`).
- `zero` / `one` / `two` / `few` / `many` / `other` — арабский, валлийский;
  латышский использует `zero`, ирландский — `one/two/few/many/other`.
- Только `other` — японский, китайский, корейский, тайский, вьетнамский,
  индонезийский, малайский и другие языки без грамматического числа.

Полный список языков и правил — в `RULE_BY_LANG` в `nvlocale.as` и в
`tools/plural_rules.py` (эти две таблицы должны совпадать).

Добавить новый язык с нестандартным правилом: написать функцию правила в
`plural_category()` и завести константу `R_*`, добавить язык в `language_rule()`.
Если язык укладывается в существующее правило — достаточно добавить строчку
в `language_rule()`.

## Линтер

```sh
python3 tools/lng_lint.py                 # все catalogs/*.lng против en
python3 tools/lng_lint.py catalogs/ru.lng
python3 tools/lng_lint.py --strict        # предупреждения тоже ошибка
```

Проверяет:

- синтаксис: нет разделителя, пустой ID, пробел в ID, дубликат;
- ID, которые не переведены или которых нет в базовом каталоге;
- подстановки: перевод не должен использовать `{N}`, который вызывающий код
  не передаёт; потерянная подстановка — предупреждение;
- формы множественного числа: недостающие для этого языка — предупреждение,
  мёртвые (язык их никогда не использует) — тоже предупреждение;
- отсутствие `.other` у plural-записи — ошибка.

## Тесты

```sh
python3 tools/test_plural_rules.py       # 176 векторов CLDR
nvgt tests/test.as                       # 42 проверки на движке
nvgt examples/example.as                 # пример, результат в examples/output.txt
```

NVGT в скриптовом режиме ничего не пишет в консоль, поэтому `tests/test.as`
пишет отчёт в `tests/last_run.log` (последняя строка — `RESULT: PASS` или
`RESULT: FAIL`), а пример — в `examples/output.txt`.

## Известные ограничения

- Сербский, хорватский и боснийский в CLDR различают дробные формы по числу
  видимых знаков (`f`). `double` этого не знает, поэтому любая нецелая дробь
  считается `other`. Для целых чисел правила точные.
- `pt-PT` и `pt-BR` сведены к одному `pt`; региональные различия в правилах
  склонения для инди-игр практически не встречаются.
- `num()` без точности отдаёт то, что напечатает `string(double)`: для очень
  больших чисел это может быть экспоненциальная запись.
- Разделитель дробной части локализуется, разделитель тысяч — нет.
- В NVGT `out` — зарезервированное слово, поэтому имена переменных в библиотеке
  и примерах это учитывают.
